How to Run: Monitoring & Alerting System

Complete Quick-Reference Runbook for Docker, Local Dev, Demos & ML Intelligence
Release 2.0

1. System Services & Access URLs

When running, each service exposes dedicated web interfaces and API ports:

2. Running with Docker Compose (Recommended)

The entire multi-tier system can be built and orchestrated with a single Docker command:

# 1. Open a terminal at the project root directory
docker compose down
docker compose up --build

# (Optional) Run in background detached mode:
docker compose up --build -d
What this does: Builds and starts flask_app, ml_service, react_frontend, locust, prometheus, grafana, and alertmanager all connected via the internal monitoring_net Docker bridge network.

Verification Steps:

  • Open React Frontend: http://localhost:5173 → Check API badge is Online and ML Engine is Active.
  • Open Prometheus Targets: http://localhost:9090/targets → Verify flask_app and ml_service targets are UP.
  • Open Grafana: http://localhost:3000 → View pre-provisioned Flask dashboards.

Stopping the Docker System:

docker compose down

3. Running Locally (Development Mode)

If running without Docker Desktop, launch each service in its own terminal window:

Terminal 1: Flask Backend (5000)

# From project root:
python app/src/app.py

Starts API on http://localhost:5000 with health, metrics, and demo endpoints.

Terminal 2: ML Service (5001)

# From project root:
python ml_service/app.py

Loads Isolation Forest model and listens on http://localhost:5001.

Terminal 3: React Frontend (5173)

cd frontend
npm install
npm run dev

Starts Vite dev server at http://localhost:5173 with reverse proxy enabled.

Terminal 4: Locust (Optional)

cd load-testing\locust\scripts
locust -f locustfile.py

Web UI opens at http://localhost:8089.

4. Interactive Locust 1-Minute Demo Scenarios

Two specialized 60-second automated load scenarios are included to demonstrate observability, latency surges, and error storms:

Scenario 1: demo_latency

60 Seconds

Pattern: Normal traffic (0–20s) → Surge of /slow requests (20–40s) → Recovery (40–60s).

Expected Behavior: P90 Latency elevates to ~2.0s during middle spike while error percentage stays at 0%. System fully recovers after 60s.

Scenario 2: demo_errors

60 Seconds

Pattern: Normal traffic (0–20s) → Surge of both /slow and /error requests (20–40s) → Recovery (40–60s).

Expected Behavior: Both latency AND error percentage (~35–45%) surge during the middle spike. Triggers critical alerts and high ML risk.

How to Trigger Demos:

  1. Option A: One-Click from Frontend UI (Easiest)
    Navigate to http://localhost:5173 → In the Interactive Locust Demo Scenarios section, click either:
    Displays 60s countdown, real-time request rate, P90 latency, error rate, and live graph plotting.
  2. Option B: Via PowerShell CLI
    Run directly from PowerShell without opening a browser: 
    cd load-testing\locust\scripts
.\collect_dataset.ps1 -Scenario demo_latency
# OR
.\collect_dataset.ps1 -Scenario demo_errors
  3. Option C: Via REST API
    # Start demo:
curl -X POST http://localhost:5000/api/demos/start -H "Content-Type: application/json" -d "{\"scenario\": \"demo_latency\"}"

# Poll status:
curl http://localhost:5000/api/demos/active
Concurrency Protection: Only one demo can run at any time. Attempting to start a second demo while one is running returns an HTTP 409 Conflict error with the remaining seconds.

5. Frontend Key Features & Live Testing

A. Real-Time Inputs Graph (Traffic, Latency, Errors)

  • Renders live time-series SVG curves for Traffic Rate (Indigo), P90 Latency (Amber), and Error Rate (Rose).
  • Hover over any point to view exact timestamp and metric values. Toggle series pills to hide/isolate specific metrics.
  • Updates automatically every 2–3s, during Locust demo spikes, or when custom inputs are evaluated.

B. Anomaly Simulator & Custom Input Evaluation

  • Adjust the 4 input sliders (Request Rate, Error Rate, P90 Latency, Requests In-Progress) or click any preset (Normal Baseline, Ramp Up Load, Traffic Spike, Heavy Error Storm).
  • Click Evaluate Custom Inputs → The status immediately updates to High Risk, Medium Risk, or Normal with updated triggers and meter.
  • Click Reset Live to return to live background metrics polling.

C. Offline Status Test (Simulating API Down)

  1. Stop the Flask backend process or container: docker stop flask_app (or press Ctrl + C in Terminal 1).
  2. Watch the Status Hero Banner immediately turn RED displaying:
    Status: App is Down  |  [OFFLINE]  |  Port 5000 Unreachable
  3. Restart the backend (docker start flask_app or python app/src/app.py) → Status recovers to green/normal automatically.

# Alertmanager

## Purpose
Alertmanager is responsible for **handling alerts generated by Prometheus**.

In this project, Alertmanager answers:
“Once a problem is detected, how is it surfaced automatically without manual monitoring?”

Alertmanager does not detect problems itself.  
It **receives alerts from Prometheus**, manages them, and makes them visible to operators.

---

## What Alertmanager Does in This Project
- Receives alerts fired by Prometheus alert rules
- Groups and manages active alerts
- Displays alerts in a central web UI
- Serves as the notification routing layer

Alertmanager ensures that engineers are **not required to continuously check dashboards** to know when something is wrong.

---

## What Was Installed
- Alertmanager (Windows binary)
- amtool (bundled with Alertmanager, used for validation)

Alertmanager runs as a **separate service** from Prometheus.

## Configuration Summary

### alertmanager.yml
Defines:
- Global alert handling behavior
- Alert routing logic
- Alert receivers

In this project, a **minimal configuration** is used with a single default receiver.  
This setup is sufficient to demonstrate end-to-end alert delivery without relying on external services.

---

## How to Run Alertmanager

From the Alertmanager binary directory:

```bat
alertmanager.exe --config.file=..\config\alertmanager.yml
````

Alertmanager runs at:

```
http://localhost:9093
```

---

## Verification Steps

### 1. Validate the configuration

From the Alertmanager binary directory:

```bat
amtool.exe check-config ..\config\alertmanager.yml
```

Expected output:

```
SUCCESS
```

---

### 2. Verify Alertmanager UI

Open in a browser:

```
http://localhost:9093
```

The Alertmanager web interface should load successfully.

---

### 3. Verify alert delivery from Prometheus

When a Prometheus alert fires:

* The alert appears automatically in the Alertmanager UI
* No manual dashboard checking is required

This confirms:

```
Prometheus → Alertmanager → Operator
```

---

## Design Notes

* Alertmanager handles **alert routing and visibility**, not metric evaluation
* Notification channels such as email, Slack, or webhooks are supported but not configured in this project
* External notifications are considered future enhancements

The focus of this implementation is to demonstrate **automatic alert detection and escalation** in a clear and reliable manner.
